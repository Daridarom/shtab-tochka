# Editorial Preflight — пилот локальной проверки текста и метаданных

Статус: прототип в безопасной ветке. **Не подключён к production-gate, не выполняет публикацию и не редактирует документы**. Его назначение — подготовить доказательный отчёт для редактора.

## Запуск

```bash
python3 tools/editorial_preflight.py path/to/document.docx --out preflight.json
python3 -m pip install 'pypdf==6.20.1'  # только для PDF; отдельное проверенное окружение
python3 tools/editorial_preflight.py path/to/document.pdf --out preflight.json
python3 tests/editorial_preflight.test.py
```

Вход: локальный TXT, Markdown, DOCX или PDF. EPUB и прочие форматы возвращают NOT RUN до поддержки. Отчёт JSON содержит SHA-256 исходного файла, статусы `PASS / FIX / REVIEW / FAIL / NOT RUN / N/A`, признаки и местоположение в символах, но **не включает полный текст произведения**. Код не отправляет документы в сеть, не меняет свойства, не генерирует искусственные даты, не делает заключений «написано человеком/ИИ». `PASS` сканера не заменяет ручную приёмку и не разрешает публикацию.

## Проверяемые области

- DOCX: основные свойства (title, author, subject, keywords, даты), недостающие поля, tracked changes, комментарии, скрытый текст, внешние связи и макросы.
- PDF: свойства Info, частичная сверка XMP Title, наличие текстового слоя, подозрительные действия и каталог имён. Наличие скрытых объектов не может быть полноценно исключено этим сканером, поэтому hidden остаётся REVIEW.
- Все читаемые тексты: несколько служебных фрагментов, незаполненные поля и риторические формулы как **редакторские сигналы**, а не доказательства ИИ.
- Протокол: отсутствие доступной библиотеки для PDF означает NOT RUN, а не PASS.

## Обязательная ручная приёмка

Проверить содержание и авторство фактов, сверить источник цитат, реальный голос автора и жанр. Открыть DOCX/PDF в конечном просмотрщике, проверить страницы, шрифты, иллюстрации, сноски, ссылки, колонтитулы и при необходимости электронные подписи. Проверить приватность, права и согласование. Поле Producer в PDF должно отражать фактический инструмент создания, а не имитировать другое ПО.

## Границы

Результат зависит от формата, прав доступа, качества источника и парсера. Сканер не определяет плагиат, подлинность личного опыта, юридическую корректность, полноту PDF XMP, а также provenance/Content Credentials. Часть сложных и скрытых элементов требует отдельного инструмента и ручной проверки. Подключение сканера к рабочему процессу — отдельный этап с безопасным тестированием и одобрением согласно действующему релизному порядку.

Не загружать в публичный репозиторий реальные рукописи, отчёты, имена клиентов, PDF с приватными данными или отчёты, содержащие персональные сведения. GitHub CI использует только синтетические тестовые документы.
